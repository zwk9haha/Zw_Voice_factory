> 当前项目目录：G:\Desktop\Zw_factory\Zw_Voice_factory

> 文档状态：阶段 1 最小工作流运行内核已落地；阶段 2 已接入分析、匹配、参考文本、双路线渲染、RVC 稳定层、节目响度和合并导出节点；阶段 4 的首版 Workflow Studio 已接入平台首页，支持 Manifest 节点库、端口连线、草稿校验、保存、发布、运行输入、节点状态和运行控制。

## 1. 最终目标

Zw Voice Factory 不再只是“小说配音软件”，而是一个本地优先的音声生产平台。

平台将文本分析、角色建模、声音匹配、参考音频生成、TTS 渲染、RVC 处理、音频后期和导出封装为可组合能力。用户可以像使用 Dify 工作流一样，将这些能力组合成不同的生产流程。

原有的“多角色长篇文本配音”保留为一个成熟的固定工作流模板，而不是平台唯一的使用方式。

最终产品定位：

> 面向文本到音频生产的本地化、可复用、可审核、可恢复的音声工作流平台。

## 3. 需要改变的核心思想

当前系统主要是固定页面调用固定 API：

    页面 -> 固定业务接口 -> 固定流程

目标系统应该变成：

    工作流定义 -> 节点编排 -> 节点执行器 -> 统一资源与任务状态

因此下一阶段的重点不是先制作一个漂亮的画布，而是先建立稳定的节点契约、运行状态机和资源引用机制。可视化编辑器应建立在这些基础之上。

## 4. 平台分层

### 4.1 工作流定义层

保存用户或系统预设的工作流：

- 工作流名称、版本和描述。
- 节点列表。
- 节点类型和节点配置。
- 节点输入输出端口。
- 节点之间的连线。
- 默认参数和用户可编辑参数。
- 错误处理策略。
- 是否允许暂停、重试、跳过和恢复。

### 4.2 工作流运行层

负责一次工作流运行，而不是负责具体模型：

- 创建、启动、暂停、恢复、取消和重试。
- 根据依赖关系调度节点。
- 持久化节点输入、输出、状态和耗时。
- 管理并发数量和资源锁。
- 处理节点失败、重试、跳过和回退。
- 支持从已完成节点恢复，不重复执行有效缓存。
- 输出统一的运行日志和进度事件。

### 4.3 能力节点层

把现有后端服务包装成可复用节点：

- 文本导入、文本切片。
- 角色候选分析、角色候选审核。
- 声线画像、说话人分配、导演文件。
- 声音库搜索、声音匹配。
- 参考文本、参考音频、情绪派生。
- 质量 TTS、极速 TTS。
- RVC 身份转换、RVC 稳定层。
- 节目级响度处理、音频合并、流式播放和导出。

### 4.4 资产与项目层

统一管理：

- 项目、源文档和任务。
- 角色和角色版本、声线画像。
- 参考音频和情绪音频。
- 导演文件和切片版本。
- RVC 训练集、模型版本和基准报告。
- TTS、RVC、响度处理的派生音频。
- 缓存、运行历史和导出文件。

节点之间优先传递项目 ID、资源 ID、版本 ID 和结构化 JSON，不直接依赖页面内存或大量临时文件。

## 5. 统一节点契约

每个节点至少应具备以下信息：

    node_id
    node_type
    version
    inputs
    outputs
    config
    status
    progress
    error
    started_at
    finished_at
    cache_key

节点状态统一为：

    pending
    queued
    running
    paused
    completed
    failed
    cancelled
    skipped

节点执行结果必须能表达：

- 产生了哪些资源。
- 使用了哪些模型和参数。
- 命中了哪些缓存。
- 失败原因是什么。
- 是否可以重试。
- 是否允许使用回退资源。
- 输入和输出的版本关系。

## 6. 首批节点的建议输入输出

### 文本分析节点

输入：

- SourceDocument ID 或文本内容。
- 分析模式。
- 本地粗筛和云端 API 配置。
- 并发和重试设置。

输出：

- AnalysisAudit ID。
- 角色候选。
- 说话人证据。
- 情绪和表演要求。
- 警告和置信度。

### 声线画像节点

输入：

- CharacterEvidencePack ID。
- 用户自定义属性。
- 声线描述规范版本。

输出：

- CharacterVoiceProfile ID。
- 结构化声学属性。
- 交付用声线描述。
- 约束和禁用属性。

### 声音匹配节点

输入：

- 声线画像。
- 项目 ID。
- 全局音色库筛选条件。
- 模型兼容性要求。

输出：

- 匹配候选及分数。
- 匹配依据。
- 需要用户确认的项目。
- Project Voice Snapshot 建议。

### 参考音频节点

输入：

- 声线画像或已选音色。
- 参考文本。
- 模型配置。
- 音频质量参数。

输出：

- Canonical Reference 候选。
- 音频文件和波形信息。
- 模型、参数和来源记录。

### TTS 渲染节点

输入：

- Director Document 或文本片段。
- SpeakerAssignment。
- 项目声音快照。
- 质量或极速路线配置。

输出：

- Audio Asset。
- 句级状态。
- 缓存键。
- 播放和导出地址。

### RVC 节点

输入：

- 基础音频。
- 已审核 RVC 模型版本。
- RVC 路线和推理参数。

输出：

- RVC 派生音频。
- 模型版本。
- 推理参数。
- 质量和基准状态。

## 7. 固定工作流模板

### 7.1 长篇多角色配音

    导入源文档
      -> 章节识别与切片
      -> 本地快速粗筛
      -> 云端或本地精析
      -> 角色候选审核
      -> Character Voice Bible
      -> 声线画像
      -> 声音匹配或参考音频生成
      -> Director Document
      -> 质量或极速渲染
      -> 可选 RVC 稳定层
      -> 节目级响度处理
      -> 流式试听与导出

长篇工作流必须保持以下行为：

- 按用户设置的章节数或文本量形成 Production Slice。
- 第一切片达到可渲染状态后即可进入质量试听。
- 后续切片在滚动窗口内后台准备。
- 相同角色复用项目声音快照，不重复生成参考音频。
- 失败可以按节点、阶段或切片恢复。
- 后续切片不能覆盖已审核的角色和声音版本。

### 7.2 短文本快速配音

    输入短文本
      -> 分析说话人和情绪
      -> 匹配项目或全局声音库
      -> 没有合适声音时生成候选
      -> 用户试听并接受
      -> 生成最终音频
      -> 导出

### 7.3 用户提供参考音频

    输入文本
      -> 上传参考音频
      -> 可选生成声线画像
      -> 分析情绪和表达
      -> TTS 生成
      -> 音频后处理
      -> 导出

### 7.4 基础音色库生产

    声线标签与详细描述
      -> 标准参考文本
      -> 高质量参考音频
      -> 人工试听审核
      -> 发布为音色库版本

## 8. 资源复用和版本规则

匹配优先级固定为：

1. 当前项目已经接受的 Project Voice Snapshot。
2. 用户明确收藏或锁定的全局 Voice Catalog 版本。
3. 满足性别、年龄、风格、情绪和模型兼容性的全局候选。
4. 项目内相似角色或通用 Archetype Voice。
5. 生成新的参考音频。
6. 使用有记录的旁白或通用音色回退。

禁止静默替换声音。每次复用、替换和回退都必须记录：

- 目标角色和项目。
- 实际使用的声音版本。
- 匹配依据和置信度。
- 用户是否确认。
- 受影响的切片和音频。
- 是否需要重新渲染。

全局音色库中的版本必须不可变。项目绑定具体版本后，全局音色库的新版本不能自动修改项目结果。

## 9. 推荐实施顺序

### 阶段 0：冻结领域边界

目标：让现有页面和后端服务使用同一套术语和资源 ID。

工作：

- 确认 VoiceProject、VoiceTask、AudioAsset、VoiceSnapshot 等模型边界。
- 检查现有 JSON、文件缓存和 API 返回是否能表达资源版本。
- 对已有服务补充稳定的输入输出 DTO。
- 记录当前仍依赖页面状态的接口。

完成标准：不引入画布，现有小说和短文本流程功能不退化，核心服务可以被独立调用。

### 阶段 1：实现工作流运行内核

目标：先能运行一个没有画布的 JSON 工作流。

工作：

- 新增工作流定义模型。
- 新增工作流运行和节点运行模型。
- 实现拓扑排序和依赖调度。
- 实现统一状态、进度、日志、错误和取消。
- 实现节点缓存键和已完成节点跳过。
- 提供创建、启动、查询、暂停、恢复、重试和取消 API。

建议先使用内存调度加 JSON 持久化，稳定后再评估 SQLite；不要一开始引入 Redis、Kafka 或微服务集群。

当前实现：`backend/app/workflows.py` 提供 JSON 持久化的工作流定义、运行实例和节点运行状态；支持拓扑依赖校验、节点缓存跳过、查询、暂停、恢复、取消和失败重试。内置节点类型包括 `text.import`、`text.input`、`text.analysis`、`voice.character_analysis`、`voice.profile`、`voice.match`、`voice.reference_text`、`voice.reference_audio`、`voice.quality_render`、`voice.fast_render`、`voice.rvc_stability`、`voice.program_loudness` 和 `voice.merge`。`text.import` 可从运行输入或工作区内 TXT 文件导入剧本，并传递 `source_name` 与 `project_id`；文本分析复用平台统一的 `TextSegment`/`SpeakerAssignment` 契约；声音匹配复用 `VoiceCatalogService`，返回带分数和匹配依据的候选，不会静默绑定项目声音快照。参考音频、双路线渲染、RVC 重处理、响度重处理和合并导出均通过现有 `JobService` 执行，不复制模型队列或 FFmpeg 逻辑。

公开接口位于 `/api/workflows`：创建定义后，可以通过 `POST /api/workflows/{workflow_id}/runs` 启动运行，通过 `GET /api/workflows/runs/{run_id}` 查询，并调用 `/pause`、`/resume`、`/retry`、`/cancel` 控制运行。

完成标准：一个包含文本输入、声线画像和参考音频生成的 JSON 工作流能够启动、查询、失败重试和恢复。✅

### 阶段 2 当前进度

已完成两组通用节点适配：

- `text.analysis`：将文本切分为统一 `TextSegment`，输出说话人分配和情绪标签。
- `voice.character_analysis`：按明确说话人聚合证据并生成结构化角色画像，供后续节点继续引用。
- `voice.match`：按性别、年龄段、音色/表达标签和声线描述对全局 `Voice Catalog` 排序，输出可解释分数、依据、版本和参考音频状态。
- `POST /api/voice-catalog/match`：提供同一套只读匹配能力，便于短文本页面和工作流共用。
- `voice.reference_text`：通过 `PreparationService` 的公共接口复用规则、本地或云端分析器，生成可追溯的标准参考文本。
- `voice.quality_render`：复用现有质量渲染任务，支持外部参考音频或声音库版本；使用声音库时必须显式锁定 `catalog_version_id`。
- `voice.fast_render`：复用现有极速路线任务，并统一输出任务详情、响度指标和 `audio_asset` 来源链。
- `voice.rvc_stability`：接收 `project_id` 与已完成质量任务的 `job_ids`，复用质量 RVC 稳定层；输出每个任务的 RVC 状态、模型 ID、基础/RVC/最终音频地址和来源链。RVC 不可用、未批准或绑定缺失时沿用 JobService 的明确回退状态，不声称已应用。
- `voice.program_loudness`：接收 `project_id` 与已完成质量/极速任务的 `job_ids`，复用响度重处理；输出更新后的任务、音频地址、响度指标和 `audio_asset`。
- `voice.merge`：接收 `project_id`、`route`（`quality` 或 `fast`）与任务列表，复用节目级合并及响度归一；输出合并 WAV 地址、片段数、时长、节目响度指标和导出 `audio_asset`。跨项目、未完成任务和路线不匹配会使节点失败并持久化错误。

分析与匹配节点仍然只负责候选建议；项目快照的接受、候选生成、版本升级和 Match-or-Generate 决策保持显式操作，避免全局资产更新影响已有项目。`PlatformService` 将快照和决策写入项目 `voice/snapshots`、`voice/decisions` 目录，并把已接受音频复制到项目资源路径；下一步继续补齐短文本渲染闭环，再评估把固定小说流程迁移为模板。

### 阶段 2：包装现有服务为节点

目标：复用现有实现，而不是复制一套业务逻辑。

优先顺序：

1. 文本输入节点。
2. 文本分析节点。
3. 声线画像节点。
4. 声音匹配节点。
5. 参考文本节点。
6. 参考音频节点。
7. TTS 渲染节点。
8. 音频后处理和导出节点。
9. RVC 节点。

每个节点先提供后端适配器，再由现有页面调用同一适配器。不要让旧页面和工作流分别维护两套模型调用逻辑。

完成标准：短文本快速配音和小说主流程都可以调用通用节点，同时保留原有页面体验。

### 阶段 3：把固定流程迁移为模板

目标：让“小说配音”成为平台模板，而不是写死在页面中的流程。

工作：

- 将长篇小说流程保存为版本化工作流模板。
- 将章节切片、角色审核和长篇滚动窗口作为场景专用节点。
- 保留小说专有数据，不把章节字段硬塞进通用任务模型。
- 一键流程改为启动一个固定工作流运行。
- 将已有断点恢复接入统一运行状态。

完成标准：用户仍然可以一键完成小说配音，但每个阶段可以在运行详情中看到对应节点和资源。

### 阶段 4：制作工作流编辑器

目标：提供类似 Dify 的可视化编排体验。

当前进度：首版编辑器已落地为 `frontend/src/WorkflowStudio.tsx`，并通过平台首页“工作流编排”入口访问；后端 `/api/workflows/node-types`、`/validate`、定义更新和发布接口已接入。现已支持发布工作流的完整运行、输入 JSON、节点状态轮询、暂停/恢复/取消/重试和最终输出查看；单节点运行仍待补齐。

工作：

- 展示节点分类和输入输出端口。
- 支持拖拽、连线、删除、复制和配置节点。
- 支持工作流保存、版本、复制和模板化。
- 对不兼容的端口显示明确错误。
- 对需要人工审核的节点显示人工检查点。
- 提供运行预览、单节点运行和完整运行。

编辑器只负责工作流定义，不直接执行模型。执行仍由后端工作流运行层负责。

完成标准：用户可以组合“声线描述 + 参考音频生成 + TTS”形成一个短文本工作流，并且可以保存后重复运行。

### 阶段 5：补齐通用场景适配器

建议顺序：

1. 普通剧本和对白。
2. 字幕文件。
3. 短视频脚本。
4. 播客和节目稿。

这些适配器只负责把各自输入转换为统一的 TextSegment 和 SpeakerAssignment，不能复制小说分析、缓存和渲染实现。

## 10. 当前阶段不要做的事情

- 不要先把全部代码拆成微服务。
- 不要为了画布 UI 重写现有稳定的 TTS、RVC 和长篇逻辑。
- 不要让云端模型直接写入全局音色库。
- 不要把角色长期声线和句子级情绪重新合并。
- 不要让节点直接读取其他节点的页面内存状态。
- 不要默认每次运行都重新生成参考音频。
- 不要用一个万能提示词替代证据、角色审核和说话人分配。
- 不要在没有基准审核的情况下自动启用 RVC 稳定层。
- 不要在平台运行链路中绕过 Start-ZwVoice.cmd 直接启动服务。
- 不要在工作流基础设施稳定前继续无边界增加新的模型后端。

## 11. 验收标准

### 基础运行

- 工作流可以创建、启动、查询、暂停、恢复、取消和重试。
- 节点状态和整体状态一致，不会出现前端显示完成但后端仍在运行。
- 启动器仍然是唯一的正式服务入口。
- 启动器停止时可以回收工作流及其模型进程。

### 数据和资源

- 节点输入输出可以追溯到项目、任务和版本。
- 已完成节点可以命中缓存并跳过。
- 声音版本不会被静默替换。
- 失败重试不会破坏已经接受的角色和声音资产。

### 小说工作流

- 仍支持用户设置每个切片包含的章节数。
- 第一切片可以先进入质量渲染。
- 后续切片能够后台继续准备。
- 相同角色可以跨切片复用声音资源。
- 可以从失败切片继续，而不是整本重新开始。

### 短文本工作流

- 用户可以只输入几句文本。
- 可以组合声线描述、参考音频和 TTS 节点。
- 可以从基础音色库匹配声音。
- 匹配失败后才生成新参考音频。
- 生成结果可以试听、缓存和导出。

### 可观测性

- 每个节点显示输入摘要、输出摘要、状态、耗时和错误。
- 模型调用显示必要的请求阶段和返回阶段信息。
- 敏感 API Key 不进入日志。
- 运行日志可以在启动器和 WebUI 中查看。

## 12. 新会话启动说明

新会话开始时应先读取以下文件：

1. AGENTS.md
2. CONTEXT.md
3. docs/VOICE_PLATFORM_EXPANSION_TASK.md
4. docs/architecture.md
5. docs/VOICE_WORKFLOW_PLATFORM_NEXT_SESSION.md

然后检查：

    .\Start-ZwVoice.cmd status
    git status --short

项目正式启动、测试和停止必须使用：

    .\Start-ZwVoice.cmd run
    .\Start-ZwVoice.cmd test
    .\Start-ZwVoice.cmd stop

新会话的第一个开发任务建议是：

> 先设计并实现最小可用的工作流运行内核，支持文本输入、声线画像、参考音频三个节点；暂不制作可视化画布，先让 JSON 工作流可以持久化、运行、查询进度、失败重试和恢复。

## 13. 项目成功标准

项目完成平台化后，用户不应只看到“小说导入”按钮，而应看到：

    新建音声项目
      -> 选择内容类型或工作流模板
      -> 输入或导入文本
      -> 分析说话人和表达要求
      -> 匹配已有声音
      -> 缺失时生成候选
      -> 用户审核
      -> 生成、试听和后处理
      -> 保存到项目或发布到声音库
      -> 导出结果

小说仍然是最能体现平台复杂能力的场景，但不再限制平台的产品边界。
