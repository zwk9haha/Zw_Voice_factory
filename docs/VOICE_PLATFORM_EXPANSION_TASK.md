# 音声平台泛化改造任务书

> 文档状态：已确认方向，作为后续拆分开发任务的基线。
>
> 目标：在不破坏现有小说配音链路的前提下，把项目从“小说配音工作站”扩展为“通用音声生产平台”。

## 当前实现进度

第一批平台化改造已经落地：平台首页、`VoiceProject`/`VoiceTask` 基础契约、短文本快速分析任务、小说项目场景适配器、统一任务持久化、基础音色库、Voice Capability 入口和启动器回归测试已经可用。阶段 1 的最小 JSON 工作流运行内核也已接入，支持依赖调度、缓存、查询、暂停/恢复、取消和失败重试。阶段 2 已接入文本分析、角色分析、声音库匹配、参考文本、参考音频、质量渲染和极速渲染节点；短文本页面与工作流可共用同一套 `TextSegment`、`SpeakerAssignment`、声音匹配及现有渲染任务实现。声音库渲染会锁定具体版本，避免全局资产更新导致运行结果漂移。

仍未完成的部分是短文本页面的完整渲染闭环和其他场景适配器；项目声音快照与 Match-or-Generate 已提供后端接口和短文本工作台交互。通用工作流已补齐音频后处理、RVC 稳定层和合并导出节点。当前短文本分析结果仍会明确标出“暂无匹配声音”，不会假装已经完成声音复用。

## 一、已经确定的方向

当前项目已有的文本分析、角色审核、参考音频、导演文件、质量渲染、极速路线、RVC、流式试听和长篇切片能力继续保留。

本次不是推倒重做，而是增加一层通用平台外壳：

```text
音声平台
├─ 通用生产内核
│  ├─ 文本分析
│  ├─ 说话人分配
│  ├─ 声音匹配
│  ├─ 缺口声音生成
│  ├─ TTS/RVC 渲染
│  ├─ 试听、缓存、版本和导出
│  └─ 任务状态与进度
└─ 内容场景适配器
   ├─ 小说：章节、角色权重、长篇切片、导演文件
   ├─ 短文本：即时分析、匹配、试听
   ├─ 剧本/对白：场景和说话人驱动
   └─ 字幕：时间轴和批量渲染
```

已经确认的两项架构决策：

1. 以 `Voice Project` 和 `Voice Task` 作为平台统一工作单元，小说只是一个内容场景。
2. 使用“全局声音库 + 项目声音快照”：全局资产可复用，项目固定使用的版本不被后续修改静默替换。

## 二、平台要解决的核心问题

用户不应被迫先创建一本小说、分析整本文本，才能获得一段声音。平台应该支持以下最短路径：

```text
输入几句文本
  → 分析说话人、情绪和表达要求
  → 优先匹配项目或全局声音库
  → 匹配不到时生成候选声音
  → 试听并接受
  → 生成音频、缓存并导出
```

现有小说流程则成为更复杂的长任务：

```text
导入小说
  → 章节/场景切分
  → 角色候选和证据审核
  → 角色声线档案
  → 标准参考和导演文件
  → 切片滚动生产
  → 质量/极速路线渲染
  → 流式试听和节目导出
```

两条流程必须共享角色、说话人、声音资产、缓存、渲染任务和日志，而不是维护两套互不兼容的实现。

## 三、统一领域对象

| 对象 | 责任 | 不负责的内容 |
| --- | --- | --- |
| `VoiceProject` | 保存一个内容项目及其资源、版本和生产记录 | 不直接执行单句 TTS |
| `VoiceTask` | 表示一次短文本预览、批量渲染或长篇生产请求 | 不拥有全局声音资产 |
| `SourceDocument` | 保存原始文本和来源类型 | 不决定最终音色 |
| `TextSegment` | 保存有序、可处理的文本单元 | 不等同于任意 token 窗口 |
| `SpeakerAssignment` | 把文本片段连接到角色、旁白、通用音色或回退方案 | 不生成角色声线描述 |
| `Character Voice Bible` | 保存角色跨片段的长期身份和声线基调 | 不保存句子级情绪 |
| `Director Document` | 保存句子级说话人、情绪、停顿、语速和能量 | 不覆盖角色长期身份 |
| `Voice Catalog` | 保存平台级可复用声音及其版本、来源和质量信息 | 不自动修改项目绑定 |
| `Project Voice Snapshot` | 固定项目当前使用的声音版本和项目级覆盖 | 不成为全局共享资产 |
| `Audio Asset` | 保存原始、RVC、响度处理和导出音频的来源链 | 不承担说话人判断 |
| `Production Run` | 记录任务执行、阶段、进度、失败和恢复 | 不改变已接受资产 |

## 四、当前阶段具体要做什么

### P0：建立平台外壳和统一契约

这是第一阶段，优先于新增模型。

- 增加平台首页，而不是默认直接进入小说导入页面。
- 创建 `VoiceProject`，选择内容类型：短文本、小说、剧本、字幕或普通文档。
- 统一 `VoiceTask` 的创建、启动、暂停、继续、取消、重试和进度接口。
- 把现有小说流程包装为 `NovelScenarioAdapter`，保持当前功能可用。
- 统一任务状态、错误、日志、缓存和输出目录的命名。
- 保证启动器仍然是唯一的服务入口，不允许新入口绕过启动器。

**验收标准：** 用户可以创建一个“短文本项目”和一个“小说项目”，两者都能进入统一任务列表；小说项目原有流程不退化。

### P1：实现短文本快速配音 MVP

- 提供文本输入框和文本类型选择。
- 支持自动识别旁白、单人对白、多人对白和未知说话人。
- 显示分析出的说话人、情绪、置信度和推荐声音。
- 优先搜索项目快照和全局声音库。
- 没有合适声音时，提供“生成候选声音”操作。
- 支持候选声音试听、接受、删除和重新生成。
- 直接生成短文本音频并支持流式试听。
- 保留每次分析和渲染的输入、输出、模型、耗时和失败原因。

**验收标准：** 输入一段包含旁白和两名角色的短文本，不创建小说章节，也能完成分析、匹配/生成、试听和导出。

### P2：建设全局声音库和项目快照

- 把现有参考音频、情绪派生、RVC 资产和质量信息整理成可索引的声音资产。
- 声音资产必须有唯一 ID、版本、来源、模型、参考文本、性别/年龄等标签、质量状态和适用范围。
- 支持搜索、标签筛选、试听、收藏、归档和删除。
- 支持从项目中“复用到当前项目”。
- 项目绑定具体版本，后续全局声音更新不能影响已有项目。
- 支持用户明确执行“升级到新版本”或“另存为项目声音”。
- 生成新声音时，先显示相似声音和复用建议，避免重复生产。

**验收标准：** 项目 A 生成并发布一个声音；项目 B 可以搜索并引用它；项目 A 后续修改不会改变项目 B 已使用的声音。

### P3：把现有小说链路接入通用内核

- 小说导入只负责解析章节、场景、人物证据和切片边界。
- 角色审核结果写入统一的角色和声音绑定模型。
- 导演文件转换为通用 `TextSegment + SpeakerAssignment`。
- 现有 50 章一切片、首切片优先、后台准备后续切片的能力继续保留。
- 相同角色跨切片复用项目声音快照。
- 低权重角色继续支持通用音色、旁白路由和明确记录的回退策略。
- 长篇任务可以从任意已完成切片恢复，不重复处理已完成资产。

**验收标准：** 小说项目和短文本项目最终都能进入相同的声音匹配、渲染、缓存和试听组件。

### P4：增加其他内容适配器

按价值顺序建议为：

1. 普通剧本/对白：文本、场景、说话人和舞台指令。
2. 字幕文件：时间轴、文本片段和批量导出。
3. 短视频脚本：旁白、角色对白、背景音乐占位和平台规格导出。
4. 播客/节目稿：段落、主持人、嘉宾和节目级响度。

这些适配器只能复用通用内核，不应再次复制小说角色分析、音频缓存和渲染队列。

## 五、建议的模块边界

```text
frontend/
  PlatformHome              平台首页、项目类型和任务入口
  ProjectWorkspace           项目资源、快照、任务和历史
  QuickVoiceTask             短文本快速配音
  VoiceCatalog               全局声音库
  ScenarioAdapters/Novel     小说导入和长篇切片界面

backend/app/
  projects                   项目和任务生命周期
  voice_catalog               全局声音资产与项目快照
  matching                   声音匹配与相似度排序
  analysis                   通用文本分析契约
  scenarios/novel            小说场景适配器
  production                 通用渲染、缓存、日志和恢复
```

第一阶段不要直接拆分当前所有大文件。先以接口和数据边界隔离，再逐步迁移内部实现，避免在功能仍不稳定时进行大规模重构。

## 六、匹配与生成策略

声音选择必须遵循以下优先级：

1. 当前项目已经接受的 `Project Voice Snapshot`。
2. 用户明确收藏或锁定的全局 `Voice Catalog` 资产。
3. 全局声音库中满足性别、年龄、风格、情绪和模型兼容性的候选。
4. 项目内相似角色或通用 Archetype Voice。
5. 生成新的参考音频或声音资产。
6. 无法生成时，使用明确记录的旁白/通用音色回退。

匹配结果必须展示：

- 匹配到的声音及版本。
- 使用了哪些标签和文本证据。
- 匹配置信度。
- 是否为项目固定资产。
- 是否需要用户确认。
- 如果生成，预计耗时和后续可复用范围。

禁止静默替换声音。任何回退都必须写入 `Production Fallback`，并允许用户回看和重新渲染。

## 七、当前不做的事情

为了避免范围失控，第一阶段明确不做：

- 多用户账号、权限和在线协作。
- 公共声音市场或对外交易平台。
- 自研基础 TTS 模型。
- 自动抓取网络声音并导入声音库。
- 让云端模型直接拥有全局声音库写权限。
- 用一个“万能提示词”替代角色证据、说话人分配和审核。
- 把所有小说专有字段硬塞进通用任务模型。
- 在平台外壳完成前继续堆叠新的 TTS 后端。

## 八、必须提前解决的风险

### 1. 声音身份污染

全局声音库中的声音可能被错误角色使用。解决方式是版本、来源、适用标签、项目快照和人工接受状态全部一等化，不能只保存一个 WAV 路径。

### 2. 自动分析错误

短文本上下文很少，角色识别置信度可能不足。需要提供“未知说话人”“用户手动指定”和“暂不生成”三种选择，不能强行猜测。

### 3. 生成成本失控

匹配优先、相似声音推荐、内容指纹和缓存命中必须先于参考音频生成。短文本模式尤其不能每次输入变化都重新训练或生成完整资产。

### 4. 模型兼容性

不同 TTS、RVC 和参考音频格式不能直接视为同一种声音。声音库需要保存模型兼容矩阵，匹配时先过滤不可用资产。

### 5. 小说链路被泛化破坏

小说章节、角色圣经和导演文件是已有稳定资产。新平台只能通过适配器接入，不能为了统一而删除小说专有能力。

## 九、测试与交付顺序

建议按以下顺序交付：

1. 数据契约和项目/任务状态测试。
2. 短文本项目创建和任务恢复测试。
3. 声音库发布、搜索、引用和项目快照测试。
4. Match-or-Generate 决策测试。
5. 短文本真实试听和音频导出测试。
6. 小说适配器回归测试。
7. 长篇切片首片优先和后台继续准备测试。
8. 启动器、日志、取消、重试和进程回收测试。

每个阶段都要通过启动器执行验证，不能直接启动前端、FastAPI 或模型 Worker 绕过正式运行链路。

## 十、最终产品形态

用户看到的不是“小说配音工具”，而是一个可以处理多种文本的本地音声工作台：

```text
新建项目
  → 选择内容类型
  → 输入或导入文本
  → 分析说话人和表达要求
  → 匹配已有声音
  → 缺失时生成候选
  → 用户审核
  → 生成和试听
  → 保存到项目或发布到声音库
  → 导出音频
```

小说仍然是最能体现平台复杂能力的场景，但不再限制平台的产品边界。
